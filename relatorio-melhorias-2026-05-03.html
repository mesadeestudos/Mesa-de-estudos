1. Resumo Executivo

As melhorias implementadas transformam o sistema de um organizador de ciclos em uma plataforma mais proativa. O usuario continua podendo alterar manualmente o plano quando necessario, mas agora o sistema interpreta sinais de desempenho, revisoes, questoes, agenda e indisponibilidade para sugerir a proxima melhor acao.

Resultado principal: o sistema ficou mais automatico sem retirar o controle do usuario. A logica dos ciclos foi preservada; foram adicionadas camadas de inteligencia, agenda, ajustes e padronizacao visual.

2. Melhorias Implementadas

4.2 Criar tabela de ajustes do plano

Necessaria para pausa do plano e reducao temporaria de meta diaria. O SQL tambem esta em scripts/create-ajustes-plano-table.sql. 

CREATE TABLE IF NOT EXISTS planejamento.ajuste_plano_usuario (
  id_ajuste_plano BIGSERIAL PRIMARY KEY,
  id_usuario BIGINT NOT NULL,
  tipo VARCHAR(30) NOT NULL,
  data_inicio TIMESTAMPTZ NOT NULL,
  data_fim TIMESTAMPTZ NOT NULL,
  horas_por_dia NUMERIC(4,2) NULL,
  motivo TEXT NULL,
  data_criacao TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT ajuste_plano_tipo_check CHECK (tipo IN ('PAUSA', 'META_TEMPORARIA')),
  CONSTRAINT ajuste_plano_periodo_check CHECK (data_fim >= data_inicio),
  CONSTRAINT ajuste_plano_horas_check CHECK (horas_por_dia IS NULL OR (horas_por_dia >= 1 AND horas_por_dia <= 12))

CREATE INDEX IF NOT EXISTS idx_ajuste_plano_usuario_periodo
  ON planejamento.ajuste_plano_usuario (id_usuario, data_inicio, data_fim);

CREATE INDEX IF NOT EXISTS idx_ajuste_plano_usuario_tipo
  ON planejamento.ajuste_plano_usuario (id_usuario, tipo);

4.3 Alinhar coluna da tabela sessao_estudo

O Prisma/schema espera a coluna planejamento.sessao_estudo.id_ciclo_disciplina. O banco real apresentou erro porque ela nao existe. A Agenda foi protegida com consulta seletiva, mas para funcionamento perfeito e sem surpresas o banco deve ser alinhado. 

ALTER TABLE planejamento.sessao_estudo
  ADD COLUMN IF NOT EXISTS id_ciclo_disciplina BIGINT NULL;

CREATE INDEX IF NOT EXISTS idx_sessao_estudo_ciclo_disciplina
  ON planejamento.sessao_estudo (id_ciclo_disciplina);

ALTER TABLE planejamento.sessao_estudo
  ADD CONSTRAINT fk_sessao_estudo_ciclo_disciplina
  FOREIGN KEY (id_ciclo_disciplina)
  REFERENCES planejamento.ciclo_disciplina (id_ciclo_disciplina)
  ON DELETE SET NULL;
Antes de executar a constraint, conferir se planejamento.ciclo_disciplina existe no banco real com esse nome e chave primaria. Se o nome real da tabela for diferente, ajustar o SQL.

9.6 Redesign da Etapa 1 de criacao de ciclo

Arquivo principal: src/app/ciclos/page.tsx, lib/studyMethods.ts.

A primeira etapa do fluxo de criacao de ciclo foi reestruturada para ser mais objetiva. Antes, o usuario precisava definir horas por dia antes de entender por que estava criando o ciclo. Agora a hierarquia e invertida: o momento de estudo e a escolha principal, as horas sao consequencia.

  • A pergunta principal passou a ser "Qual e o seu momento de estudo?", com 6 cards em grid (2 col mobile / 3 col desktop).
  • Cada card ganhou um icone visual distinto (BookOpen, CalendarDays, AlertCircle, RefreshCw, ClipboardCheck, Zap) e realce colorido ao ser selecionado.
  • A secao de horas ficou abaixo como escolha secundaria, com um subtitulo "Sugestao para este momento: Xh" que muda dinamicamente.
  • Foi adicionado um useEffect que pre-preenche as horas com o valor sugerido ao trocar de momento (COMECO_ZERO→2h, PROVA_DATA→3h, ATRASADO→4h, REVISAR→2h, QUESTOES→2h, CICLO_AUTOMATICO→2h).
  • Os stats de impacto (sessoes/dia e max disciplinas) foram movidos para dentro do painel de horas, compactando a tela.
  • O label do step 1 no indicador de progresso passou de "Tempo" para "Perfil", refletindo a nova abrangencia da etapa.

9.7 Correcao da constraint plano_estudo_metodo_check

Arquivos alterados: repository/ciclo.repository.ts. Script: scripts/update-plano-metodo-constraint.sql.

O campo metodo em planejamento.plano_estudo possuia uma check constraint criada quando o sistema so aceitava o valor 'AUTOMATICO'. Com a introducao de lib/studyMethods.ts, o servico passou a gerar valores como TRILHA_OBJETIVO, RECUPERACAO_ATRASO etc., causando erro 500 ao finalizar a criacao de qualquer ciclo com momento diferente do padrao.

  • Criado scripts/update-plano-metodo-constraint.sql que dropa e recria a constraint com todos os valores atuais.
  • Adicionada funcao normalizarMetodoDB em repository/ciclo.repository.ts como fallback: enquanto o script SQL nao for executado no banco, o sistema grava 'AUTOMATICO' e nao quebra.
  • Apos executar o script SQL, a funcao deve ser simplificada para retornar o metodo diretamente (instrucao incluida no script).
Acao obrigatoria no banco: executar scripts/update-plano-metodo-constraint.sql para que o metodo de estudo selecionado seja persistido corretamente. Sem esse script o ciclo funciona, mas todos os planos ficam gravados com metodo AUTOMATICO.
